# UI Artistic Polish — Watercolor Sketchbook + Theme Picker — Implementation Plan

## Overview

Layer a fashion-sketchbook/watercolor treatment over the warm-editorial-boutique UI, per
`thoughts/shared/decisions/2026-07-17-ui-artistic-polish.md`: paper grain, one breathing
watercolor aura behind the paper doll (the app's only ambient motion), a brush-stroke swash
under the headline, sketchy hand-drawn empty-slot borders, per-category watercolor tint dots,
painterly cards and buttons — plus a real theme picker with **5 curated light presets**
persisted in localStorage. All of it is pure CSS gradients + inline SVG filters: **no new
dependencies, no asset files, zero behavior changes** — all 66 existing tests keep passing
unmodified.

User decisions made during planning:

- **Mobile theme picker**: tiny watercolor-dot button in the mobile header opens a pop-in row
  of the 5 theme dots (one extra tap, header stays uncluttered).
- **Outfit card wash**: each card gets a **stable tint rotated from the theme's category
  palette**, keyed off the saved outfit's id — scrapbook variety, purely decorative.
- **Token naming** (delegated to planner by the decisions doc): **semantic rename** —
  `ivory→paper`, `rosewood→accent`, `blush→wash`, `ink` stays. With 5 themes, `bg-rosewood`
  rendering teal under Sea Glass would be a lie in every component.
- **Grain layer**: paper grain sits **behind content** (a `body` background, not a fixed
  overlay) — garment images, text, and popovers stay perfectly clean; outfit cards get
  their own tooth via `.paper-card`.

## Desired End State

- The app reads as a fashion illustrator's workbook: faint paper grain everywhere, a soft
  theme-tinted aura breathing on a ~20s cycle behind the paper doll (re-blooming on Shuffle
  All), a brush swash under the headline, watercolor dots beside rail labels in category
  tints, sketchy hand-drawn "none" slots, paper-textured outfit cards with a rotating tint
  wash, and a painterly hover on Shuffle All.
- A row of 5 watercolor swatch dots (sidebar footer on desktop, header popover on mobile)
  switches the entire palette live; the choice persists in

- Every color in the app resolves through semantic tokens; the accent remains the only
  action color in every theme (buttons, links, active nav, focus).
- Reduced-motion users get a static aura and no breathing/blooming.
- Zero behavior changes: shuffle, stores, outfit persistence, repair untouched; 66 existing
  tests pass unmodified, plus new theme-storage tests.

**Verify by**: `npm run lint && npm run typecheck && npm test` all pass; manual checklist
per phase; final walkthrough across all 5 themes × both breakpoints.

### Key Discoveries

- Tailwind 4 compiles `bg-ivory` → `background-color: var(--color-ivory)` and opacity
  modifiers (`text-ink/55`) → `color-mix(...var(--color-ink)...)`, so overriding the vars per
  `[data-theme="…"]` re-themes every existing class with no component changes. `@theme` vars
  are emitted inside `@layer theme`; our unlayered `[data-theme]` blocks always win the
  cascade.
- **Swatch-dot scoping trick**: putting `data-theme="lavender"` on a picker dot re-scopes the
  token vars for that one element, so its `text-accent` paints lavender's accent even while
  the app is in another theme — the CSS theme blocks stay the single source of truth, no hex
  duplication in TS. This requires an **explicit `[data-theme="rosewood"]` block** (else the
  rosewood dot would inherit the ambient theme's vars).
- Applying the stored theme needs a tiny inline `<head>` script — a React effect would flash
  the default palette for a frame. The script applies the raw stored string blindly (an
  unknown value matches no CSS block → harmless default), and `useThemeStore` re-validates
  and corrects the attribute at module init, so **no theme-id list is duplicated in
  `index.html`**.
- The aura re-bloom needs no store changes: key the aura element on the existing cascade
  tick (`useCascade.ts:9`) — Shuffle All remounts it and the bloom keyframe replays.
- Paper grain, card texture, and the button hover overlay can share **one** `feTurbulence`
  data-URI tile stored in a `--texture-grain` custom property (a data URI is code, not an
  asset file — Decision 3 holds).
- The `--animate-rail-in` fill-mode/`animation-delay` machinery in `Rail.tsx:63-86` must not
  be disturbed; all new decoration is additive around it.

## What We're NOT Doing

- Dark theme (Decision 6) — later project; all 5 presets are light.
- Freeform per-token color editor — curated presets only.
- Decorative asset files or new dependencies (Decision 3) — everything is CSS + inline SVG.
- Floating particles, sparkles, route/page transitions.
- Any behavior/logic changes: shuffle, stores, outfit persistence, repair untouched
  (`shuffle.ts`, `outfit.ts`, `closet.ts`, `naming.ts`, `localStorageStore.ts`,
  `useShuffleStore.ts`, `useOutfitsStore.ts`, `useCascade.ts`: zero edits).
- Modifying any existing test (new test files only).
- Garment image re-processing or closet content changes.
- Favicon / meta / PWA polish.
- Hand-editing `dist/` (rebuilt via `npm run build` in Phase 5).

## Implementation Approach

Five phases, each leaving the app fully working:

1. **Semantic token rename** — mechanical, zero pixels change; makes every later phase honest
   under non-rosewood themes.
2. **Theme engine + picker** — the 5 complete token sets, storage + store + pre-paint script,
   picker UI. App is fully theme-switchable but still untextured.
3. **Sketchbook texture (static)** — grain, swash, sketchy slots, tint dots, quote wash,
   card paper/wash/shadow, button hover texture.
4. **The aura** — the one living element, on a finished stage, judged in isolation.
5. **Final sweep** — straggler greps, full gate, `dist/` rebuild, 5-theme walkthrough.

All draft hex values in Phase 2 are exactly that — **drafts for user approval**; expect to
tune them live in dev tools during Phase 2's manual check and record final values here.

Shared new CSS vocabulary (all defined in `src/index.css`):

- `.watercolor-dot` — soft-edged paint dab colored by `currentColor` (picker dots, rail dots).
- `--texture-grain` — the shared noise tile (page, cards, button hover).
- `.sketchy-slot`, `.quote-wash`, `.paper-card`, `.card-wash` + `.wash-<category>`,
  `.btn-painterly`, `--shadow-painterly` — one class per placement-map item.

export const THEMES = [

#### 3. Storage module (never throws — mirrors the localStorageStore idiom)

**File**: `src/features/theme/themeStorage.ts` (new)

```ts
import { DEFAULT_THEME, isThemeId, type ThemeId } from "./themes";

export const THEME_KEY = "joyces-closet:theme:v1";

type StorageLike = Pick<Storage, "getItem" | "setItem">;

/**
 * The value is the raw theme id, not JSON — the pre-paint script in index.html reads it
 * with a bare getItem. Anything unreadable (missing key, unknown id, storage errors)
 * degrades to the default; reading the theme must never throw.
 */
export function readTheme(storage: StorageLike = window.localStorage): ThemeId {
  try {
    const raw = storage.getItem(THEME_KEY);
    return isThemeId(raw) ? raw : DEFAULT_THEME;
  } catch {
    return DEFAULT_THEME;
  }
}

export function writeTheme(
  id: ThemeId,
  storage: StorageLike = window.localStorage,
): void {
  try {
    storage.setItem(THEME_KEY, id);
  } catch {
    // Quota/private-mode errors: the choice just won't survive a reload.
  }
}
```

No DOM access in this module — its tests run in the default node environment like
`localStorageStore.test.ts`.

#### 4. Store + DOM application

**File**: `src/features/theme/useThemeStore.ts` (new)

```ts
import { create } from "zustand";

import { readTheme, writeTheme } from "./themeStorage";
import { DEFAULT_THEME, type ThemeId } from "./themes";

/** <html data-theme> is the single CSS switch; the default theme carries no attribute. */
function applyTheme(id: ThemeId): void {
  if (id === DEFAULT_THEME) document.documentElement.removeAttribute("data-theme");
  else document.documentElement.setAttribute("data-theme", id);
}

// The pre-paint script in index.html applied the raw stored value blindly; re-validate
// here so a stale/unknown id is corrected before React renders anything themed.
const initialTheme = readTheme();
applyTheme(initialTheme);

interface ThemeState {
  theme: ThemeId;
  setTheme: (id: ThemeId) => void;
}

export const useThemeStore = create<ThemeState>()((set) => ({
  theme: initialTheme,
  setTheme: (id) => {
    writeTheme(id);
    applyTheme(id);
    set({ theme: id });
  },
}));
```

<script>
  // Apply the persisted theme before first paint so the chosen palette never flashes.
  // An unknown/corrupt value matches no CSS block (harmless default look) and is

  try {

import { useState } from "react";

import { THEMES } from "./themes";
import { useThemeStore } from "./useThemeStore";

export function ThemePicker({
  className = "",
  onPick,
}: {
  className?: string;
  onPick?: () => void;
}) {
  const theme = useThemeStore((state) => state.theme);
  const setTheme = useThemeStore((state) => state.setTheme);

  return (
    <div
      role="radiogroup"
      aria-label="Color theme"
      className={`flex items-center gap-2 ${className}`}
    >
      {THEMES.map((preset) => (
        <button
          key={preset.id}
          type="button"
          role="radio"
          aria-checked={theme === preset.id}
          aria-label={preset.label}
          title={preset.label}
          onClick={() => {
            setTheme(preset.id);
            onPick?.();
          }}
          className={`flex h-6 w-6 cursor-pointer items-center justify-center rounded-full transition ${
            theme === preset.id ? "ring-ink/35 ring-2" : "hover:scale-110"
          }`}
        >
          {/* data-theme re-scopes the tokens: this dot paints ITS theme's accent
              regardless of the app's active theme. */}
          <span
            data-theme={preset.id}
            aria-hidden="true"
            className="watercolor-dot text-accent h-4 w-4"
          />
        </button>
      ))}
    </div>
  );
}
```

  height: 45%;

  animation: aura-breathe 27s ease-in-out -13s infinite alternate;
}

@keyframes aura-breathe {
  from {
    opacity: 0.5;
    transform: scale(1) translate(0, 0);
  }
  to {
    opacity: 0.75;
    transform: scale(1.08) translate(2%, -2%);
  }
}
@keyframes aura-bloom {
  from {
    opacity: 0;
    transform: scale(0.92);
  }
  to {
    opacity: 1;
    transform: scale(1);
  }
}
```

And extend the reduced-motion block (`src/index.css:46-54`) — the global 0.01ms clamp would
leave `infinite alternate` looping frantically, so kill the aura animations outright there:

```css
@media (prefers-reduced-motion: reduce) {
  /* …existing clamp rules… */
  .aura,
  .aura > div {
    animation: none; /* static aura: bloom's `both` fill is skipped; blobs rest at 0.6 */
  }
}
```

Differing prime-ish durations + negative delays keep the three blobs permanently out of
phase, so the composite never visibly repeats.

## Performance Considerations

- Aura animates `transform`/`opacity` only; `filter: blur()` values are static — three
  composited layers, no layout/paint thrash. Verify no continuous high CPU in devtools.
- The grain tile is one small tiled SVG data-URI decoded once and reused by page, cards, and
  button hover.
- Theme switch = one attribute flip on `<html>`; only `ThemePicker` subscribes to the theme
  store, so no rail/card re-renders.
- The `#sketchy` displacement filter applies to tiny static elements (empty-slot borders,
  the swash) — negligible.
